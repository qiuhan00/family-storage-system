# 家庭收纳物品管理系统 — 设计文档

- 日期：2026-09-24
- 状态：已评审
- 技术栈：Vue 3 前端 + Java Spring Boot 3 后端 + MySQL 8
- 部署形态：本地原生开发直跑（本机 MySQL 5.7 兼容），生产非容器部署（JDK 运行 jar + nginx 反代）

## 1. 目标与范围

家庭收纳物品管理系统：家人通过云服务器公网访问，在手机上记录、检索、管理家中物品的位置与数量，跟踪临期物品，维护缺耗品购物清单，并查看价值/盘点统计。

**功能范围（v1）**
- 物品清单、分类、位置（支持层级）与检索
- 缺耗品 / 购物清单
- 保质期站内提醒（预留短信通道扩展接口）
- 物品照片上传
- 价格与盘点统计

**非目标（范围外）**
- 条码扫码录入
- 借出 / 归还管理
- 多家庭 / 多租户隔离（单家庭共享一个库）
- 对象存储（照片存服务器磁盘）
- 短信厂商实际接入（仅定义扩展接口与配置开关，后续按需实现）

## 2. 用户与权限

- 独立账号 + 密码登录，BCrypt 哈希，JWT 无状态认证。
- 首个注册账号为 `ADMIN`；系统非空后关闭开放注册，由 ADMIN 创建成员账号。
- 角色：`ADMIN`、`MEMBER`。
  - 所有已登录成员对物品/分类/位置/购物清单/通知可读可写（家庭协作）。
  - 仅 `ADMIN`：用户管理、删除分类/位置、修改应用设置。

## 3. 总体架构

```
云端（云服务器，生产，非容器）
├─ nginx        前端静态资源 + 反代 /api、/uploads + HTTPS
├─ backend       Spring Boot 3 jar（Java 17，Maven）
│   ├─ Auth         JWT 无状态认证 + BCrypt
│   ├─ Users        ADMIN 管理成员账号
│   ├─ Catalog      分类 / 位置 / 物品 CRUD
│   ├─ Shopping     缺耗品购物清单
│   ├─ Files        图片上传（本地磁盘，路径入库）
│   ├─ Notify       NotificationChannel 接口 + InAppChannel + SmsChannel(扩展点)
│   │                + @Scheduled 每日临期扫描
│   └─ Stats        价格 / 盘点统计
└─ mysql         MySQL（utf8mb4）
```

- 前端：Vue 3 + TypeScript + Vite + Pinia + Vue Router + Vant（移动优先）+ Axios。JWT 存 localStorage。
- 后端：Spring Boot 3 + Spring Data JPA + Spring Security + springdoc(OpenAPI) + Flyway（SQL 迁移）。
- 本地开发：后端 `mvn spring-boot:run`（8080），数据库连接走本机 MySQL（`DB_PASSWORD` 环境变量）；前端 `npm run dev`（Vite 代理 `/api`）。
- 生产：`mvn clean package` 产出 jar → 云服务器装 JDK17 运行 + nginx 托管前端静态资源与反代。不使用容器编排。

**关键数据流**
- 认证：`POST /api/auth/login` → JWT → 后续请求带 `Authorization: Bearer <token>`。
- 物品：前端 CRUD `/api/items`；图片 `/api/files` 上传返回 URL，nginx 托管 `/uploads`。
- 提醒：每日调度任务扫临期物品 → 经 `NotificationChannel` 写站内通知 → 前端拉 `/api/notifications` 显示角标。
- 统计：`/api/statistics` 实时汇总总值 / 分类 / 位置 / 临期维度。

## 4. 数据模型（MySQL）

数据库 `family_storage`，utf8mb4/utf8mb4_unicode_ci（本地为 MySQL 5.7，需规避旧版 utf8mb4 索引长度上限：索引列以 `VARCHAR(100)` 为限，超长字段用前缀索引 `name(64)`）。

Flyway 迁移：`backend/src/main/resources/db/migration/V1__init.sql`。

### users 成员
`id`（PK, 自增）、`username`（unique）、`password_hash`、`display_name`、`role`（ADMIN/MEMBER）、`email`（可空）、`phone`（可空，短信扩展预留）、`enabled`、`created_at`、`updated_at`

### categories 物品分类
`id`、`name`（unique）、`sort_order`

### locations 收纳位置（层级）
`id`、`name`、`parent_id`（自引用，可空）、`sort_order`

### items 物品
`id`、`name`、`category_id`（FK categories）、`location_id`（FK locations）、`quantity`（int）、`unit`、`purchase_price`（decimal）、`purchase_date`（可空）、`expiry_date`（可空）、`photo_url`（可空）、`status`（ACTIVE/ARCHIVED）、`remark`（可空）、`created_by`（FK users）、`created_at`、`updated_at`，索引：`name`、`expiry_date`、`(category_id, location_id)`

### stock_changes 出入库记录
`id`、`item_id`（FK）、`change_qty`（正入负出）、`type`（INITIAL/IN/OUT/ADJUST）、`note`（可空）、`created_by`、`created_at`

### shopping_items 缺耗品/购物清单
`id`、`name`、`quantity`、`unit`、`category_id`（FK，可空）、`remark`（可空）、`status`（PENDING/BOUGHT/CANCELLED）、`created_by`、`created_at`、`completed_at`（可空）

### notifications 站内通知
`id`、`user_id`（FK）、`title`、`body`、`type`（EXPIRY/OTHER）、`ref_id`（关联物品 id，可空）、`reminder_key`（可空）、`read_flag`（bool）、`created_at`
唯一索引 `(user_id, reminder_key)` —— 同一物品同一到期日对每个用户只提醒一次。

### app_settings 应用设置
`key`（unique）、`value`
- `expiry.remind.days`：临期阈值，默认 `7`，ADMIN 可调。

### 关联与约束
- 物品当前存量以 `items.quantity` 为准；`stock_changes` 作审计与盘点依据。
- 删除分类/位置时若仍有 `items` 引用则拒绝（400，提示先迁移物品）。
- 删除用户：软处理（`enabled=false`，保留 `created_by` 外键引用）。

## 5. 接口规范

统一前缀 `/api`，JSON + JWT Bearer。分页响应 `{content, totalElements, totalPages, size, number}`。错误体 `{code, message}`（401 未登录 / 403 无权限 / 400 校验失败 / 404 不存在），中文 message。

### 5.1 认证 Auth
| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/auth/register` | 系统为空时注册（→ADMIN）；非空时返回 403 |
| POST | `/api/auth/login` | `{username,password}` → `{token, user}` |
| GET | `/api/auth/me` | 当前用户信息 |
| PUT | `/api/auth/password` | 修改本人密码 |

### 5.2 用户 Users（ADMIN）
| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/users` | 成员列表（分页） |
| POST | `/api/users` | 创建成员 |
| PUT | `/api/users/{id}` | 更新成员（昵称/角色/联系方式） |
| PATCH | `/api/users/{id}/status` | 启用/停用 |
| POST | `/api/users/{id}/reset-password` | 重置密码 |

### 5.3 分类 / 位置 Categories & Locations
| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/categories` / `/api/categories/{id}` | 查询 |
| POST | `/api/categories` | 新增（重名 400 `CATEGORY_NAME_TAKEN`） |
| PUT | `/api/categories/{id}` | 更新（重名 400 `CATEGORY_NAME_TAKEN`，忽略同名自身） |
| DELETE | `/api/categories/{id}` | 删除（有绑定物品则 400 `CATEGORY_IN_USE`） |
| GET/POST/PUT/DELETE | `/api/locations[/{id}]` | 同左；GET 支持树形 `parent_id`；父位置不存在 404，成环 400 `LOCATION_CYCLE`，删除有 items 引用 400 `LOCATION_IN_USE`、有子级 400 `LOCATION_HAS_CHILDREN` |

### 5.4 物品 Items
| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/items?keyword&categoryId&locationId&status&expiring=1&page&size` | 分页检索；`keyword` 对 `items.name` 做 LIKE 模糊匹配 |
| GET | `/api/items/expiring?days=7` | 临期物品列表 |
| GET | `/api/items/{id}` | 详情 |
| POST | `/api/items` | 新增（qty>0 时写 INITIAL 出入库记录） |
| PUT | `/api/items/{id}` | 更新 |
| DELETE | `/api/items/{id}` | 删除（同时归档 stock_changes） |
| POST | `/api/items/{id}/stock` | 出入库 `{deltaQty, type, note}` |
| GET | `/api/items/{id}/stock-changes` | 变更历史 |

### 5.5 缺耗品 Shopping
| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/shopping?status=` | 清单（默认 PENDING） |
| POST | `/api/shopping` | 新增缺耗品 |
| PUT | `/api/shopping/{id}` | 更新 |
| PATCH | `/api/shopping/{id}/status` | 置为 BOUGHT/CANCELLED |

### 5.6 文件 Files
| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/files` | multipart 图片 → `{url}`；限 jpg/png/webp、≤5MB |
| DELETE | `/api/files/{name}` | 删除已上传文件 |

### 5.7 通知 Notifications
| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/notifications?page&unread=1` | 我的通知（分页） |
| GET | `/api/notifications/unread-count` | 未读数 |
| PATCH | `/api/notifications/{id}/read` | 标记已读 |
| PATCH | `/api/notifications/read-all` | 全部已读 |

### 5.8 统计 Statistics
| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/statistics/summary` | `{totalItems, totalQuantity, totalValue, expiringSoon, pendingShopping}`；`expiringSoon` 固定为 `expiry.remind.days` 阈值内临期数 |
| GET | `/api/statistics/by-category` | 分类维度：物品数/总量/总值 |
| GET | `/api/statistics/by-location` | 位置维度：物品数/总量/总值 |

### 5.9 设置 Settings（ADMIN）
| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/settings` | 读取公共设置（登录成员可读，如临期阈值） |
| PUT | `/api/settings` | 更新设置（ADMIN），如 `{key:"expiry.remind.days", value:"7"}` |

## 6. 通知系统

- `NotificationChannel` 接口：`type()` + `send(NotificationContext)`。
  - `InAppChannel`：写入 `notifications` 表（v1 唯一启用实现）。
  - `SmsChannel`：扩展点预留；配置 `sms.enabled=false` 时为空实现不发送。`users.phone` 与通知通道字段已具备，未来接厂商仅需实现接口 + 配置密钥。
- 调度：`@Scheduled` 每日 09:00 扫描 `expiry_date <= today + 阈值 且 status=ACTIVE` 的物品，对每个「物品 × 每用户」生成通知，`reminder_key = EXPIRY:{itemId}:{yyyy-MM-dd}` 保证幂等去重。
- 阈值 `expiry.remind.days`（默认 7）自 `app_settings` 读取。

## 8. 部署

### 本地开发
- 数据库：本机 MySQL 5.7（服务 MySQL57），库 `family_storage`（utf8mb4）；root 密码经用户级环境变量 `DB_PASSWORD` 传入（不入代码、不入 Git）。
- 后端：`cd backend && mvn spring-boot:run`，端口 8080。
- 前端：`cd frontend && npm install && npm run dev`，Vite 代理 `/api` → 8080。

### 生产（非容器）
- 后端打包：`mvn clean package` 产出 `backend/target/*.jar`；云服务器安装 JDK 17 直接运行：
  `java -jar app.jar --spring.profiles.active=prod`（生产用外部 `application-prod.yml` 或环境变量注入 DB、`JWT_SECRET`、`UPLOAD_DIR`）。
- 前端：`npm run build` 产物 `frontend/dist/` 交给 nginx 静态托管。
- nginx 反代：`location /api` → 后端 `http://127.0.0.1:8080`；`location /uploads` → 后端上传磁盘目录（与后端共享同一 `UPLOAD_DIR`）。
- HTTPS：云负载均衡 TLS，或 nginx certbot 自动签发。
- 密钥约定：DB 口令 / `JWT_SECRET` 一律环境变量注入，不入镜像、不入 Git、不入代码。

## 9. 决策记录

| 决策 | 理由 |
|---|---|
| 前后端分离单体仓库，生产非容器部署 | 开发验证流畅；个人云服务器以 JDK+nginx 直跑最简，免去容器编排复杂度 |
| JWT 无状态认证 | 移动端/多设备友好，后端无需会话存储 |
| Flyway 迁移而非 ddl-auto | 生产环境数据可追溯、可演进 |
| 单家庭共享库、不引入租户 | 需求为单家庭；YAGNI |
| 照片存磁盘 + nginx 托管 | 量级小，避免引入对象存储复杂度 |
| 站内提醒首发 + 短信通道预留接口 | 成本可控，未来按需接入厂商 |
